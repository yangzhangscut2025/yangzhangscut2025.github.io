OpenAI Codex CLI 试用笔记：与 Claude Code 双 Agent 协作

2026-07-28 · 预计阅读 8 分钟 AI学习

公司提供了 Codex，我试用了它的 CLI 模式。本文不是官方文档的翻译，而是一个实际使用者的记录——怎么装、怎么用、和 Claude Code 怎么分工。

一、背景

在接触 Codex 之前，我已经用了几个月的 Claude Code（在 VS Code 里，配合 DeepSeek API）。日常的代码阅读、调试、写文档，基本都由 Claude Code 配合完成。

这次公司提供了 OpenAI Codex 的访问权限。Codex 有三种使用形态——桌面客户端、CLI 命令行、IDE 插件。桌面端我不需要，IDE 插件和 Claude Code 的场景高度重叠。真正让我感兴趣的是 CLI 模式：一个独立于编辑器的终端 Agent，可以和 VS Code 里的 Claude Code 并行工作。

二、Codex CLI 环境准备

前置条件

  • OpenAI 账号（Plus/Pro 账号体验更好，免费账号速率受限）
  • Node.js ≥ 22.0
  • 能稳定访问 OpenAI 服务
  • Git（可选，部分功能需要）

验证环境：

node -v    # 需 ≥ 22.0
npm -v
git --version

安装

# 国内网络可以先切镜像
npm config set registry https://registry.npmmirror.com

# 全局安装
npm i -g @openai/codex

# 验证
codex -v

登录配置

两种方式：

方式一：账号登录（推荐） 直接在终端 codex login，跳转浏览器用 OpenAI 账号授权。不需要手动管 API Key。

方式二：API Key

codex config set api_key 你的OpenAI_API_Key
codex config list   # 确认生效

安全提醒：API Key 不要写进项目配置文件里，不要提交到 Git。

三、CLI 常用命令速查

codex --help                                    # 帮助

codex generate "Go 实现 HTTP 接口请求" -o request.go   # 生成代码并保存

codex fix ./test.py                              # 纠错

codex optimize ./demo.js                         # 优化

codex comment ./main.java                        # 生成注释

基本模式就是 codex <动作> <目标文件>，和日常命令行工具的使用习惯一致。

四、CLI 还是 IDE 插件？两种模式的取舍

Codex IDE 插件（VS Code / JetBrains）和 CLI 是两种完全不同的使用场景。以下是我实际体验后的对比：

CLI 模式

优势：

  • 不依赖编辑器，任何项目、任何语言都能用
  • 支持批量处理——整个目录的代码纠错、批量加注释、跨文件重构
  • 轻量，无 GUI，低配机器也流畅
  • 可以写入 Shell 脚本，嵌入 CI/CD 流程
  • 远程服务器上唯一的可用形态（无桌面环境也能跑）

劣势：

  • 有命令行门槛，新手不如可视化直观
  • 不能实时补全——是写完代码后批量处理，不是边写边提示
  • 看不到修改预览，执行完才能打开文件看结果

IDE 插件模式

优势：

  • 边写边补全，实时纠错，贴合日常编码习惯
  • 可视化交互，右键就能触发优化、修复、生成测试
  • 自动读取项目上下文，生成的代码更贴合项目规范

劣势：

  • 强绑定编辑器，换 IDE 就不能用
  • 占用 IDE 资源，低配机器可能卡顿
  • 不适合批量处理整个项目

选型建议

场景 选择
日常手写代码、边写边改 IDE 插件
批量处理、脚本自动化 CLI
远程服务器开发 CLI（唯一选择）
新手入门 IDE 插件

五、核心发现：双 Agent 并行协作

这是我试用下来最有价值的发现——Claude Code 和 Codex CLI 不是二选一，而是互补关系。

各自的角色

Claude Code（VS Code 内） Codex CLI（终端）
定位 精读助手 全局扫描兵
工作方式 跟随你的阅读路径，交互式追问 一次性任务，独立执行
擅长 追踪数据流、跨文件调用链、深度理解 批量检索、导出清单、全局架构扫描
优势 上下文感知（知道你在看哪个文件、选中了哪段代码） 独立进程，并行运行，不阻塞编辑器

实际工作流

VS Code 窗口（Claude Code）        终端窗口（Codex CLI）
   ↓                                    ↓
"帮我梳理这个函数的调用链"          codex generate "生成项目架构文档"
   ↓                                    ↓
交互式精读，逐层追踪                全局扫描，一次输出
   ↓                                    ↓
         ← 两边并行，互不阻塞 →

具体场景：

  1. 我在 VS Code 里跟着 Claude Code 读一个模块的数据流，同时开一个终端让 Codex CLI 全仓库搜索相关引用、生成调用关系清单
  2. Claude Code 帮我理解逻辑，Codex CLI 帮我找全所有相关文件
  3. 精读和扫描同步进行，不用切窗口等

为什么不是两个都用 IDE 插件

如果 Claude Code 和 Codex 插件同时装在 VS Code 里，它们会争抢同一个上下文——都在看当前文件、都在弹补全提示、都会响应你的提问。结果是互相干扰。

把 Codex 放在终端，它就是一个独立的兵，你给它任务它就执行，不打扰你主窗口的工作流。

六、使用技巧与避坑

提高 Codex CLI 输出质量

  • 精准描述需求：明确编程语言、功能场景、约束条件，避免模糊指令
  • 分阶段执行：复杂任务拆开，先架构再函数再测试，一次给太多会出错
  • 搭配 Git 使用：Codex 改完代码后 git diff 对比差异，选择性保留
  • 定期更新：npm update -g @openai/codex，保持最新

常见问题

问题 原因 解决
安装卡住 网络连不上 npm 源 切国内镜像或换网络
登录成功但无法生成 免费账号限流 / API 额度用完 升级 Plus/Pro，查看 OpenAI 后台额度
CLI 命令不存在 npm 全局路径没加入 PATH 重启终端或手动配环境变量
生成卡顿 一次提交了太多代码 缩小范围，分步提交
响应缓慢 后台进程多 / 网络延迟 关多余进程，切本地模式

卸载

# CLI
npm uninstall -g @openai/codex

# IDE 插件
# 在插件市场找到 Codex，点击卸载，重启 IDE

七、总结

Codex CLI 本身是一个合格的命令行 AI 编程工具。但对我来说，它更大的价值在于 “第二个 Agent”——和 Claude Code 形成互补。

  • Claude Code：我的主驾驶，在编辑器里陪着我精读代码、追踪逻辑、写文档
  • Codex CLI：我的副驾驶，在终端里独立执行批量任务、全局扫描

两者并行，互不阻塞。这是单 Agent 做不到的工作方式。
