Pi 使用框架：AGENTS.md / Skills / 子代理 / MCP

2026-09-13 · 预计阅读 10 分钟 技术教程

配置完成后，下一步就是把它从一个通用的编程助手，变成真正懂你爬虫项目的专属 Agent。这套体系的核心是：用 AGENTS.md 定义“我是谁”，用 Skills 定义“我会做什么”，用子代理（Subagents） 定义“我的团队有谁”。

核心文件体系与目录结构

Pi 通过自动发现机制加载你的定制配置，所有文件都集中在 ~/.pi/agent/ 目录下：

~/.pi/agent/
├── AGENTS.md              # 全局项目指令（项目根目录的会覆盖它）
├── skills/                # 技能目录
│   └── <skill-name>/
│       └── SKILL.md       # 技能的完整定义文件
├── agents/                # 子代理定义目录
│   └── <agent-name>.md    # 每个子代理的 Markdown 定义
└── mcp.json               # MCP 服务器配置（用于联网/爬虫能力）

项目级配置放在项目根目录的 .pi/ 下，会覆盖全局配置。

第一步：编写 AGENTS.md — 定义你的项目规则

AGENTS.md 是 Agent 的“宪法”，Pi 在启动时自动加载。你不需要从零开始写，可以让 Pi 自己生成初稿：

# 进入项目目录后，在 Pi 中输入：
给这个爬虫项目写一个 AGENTS.md，包含项目结构、编码规范、常用命令和参考模板

Pi 会用 write 工具生成一份初稿，你再手动补充关键约束。一份适合爬虫重构项目的 AGENTS.md 应包含：

# 爬虫系统重构项目

## 项目结构
- src/adapters/     # 数据源适配器（每个源一个文件）
- src/fetcher/      # HTTP请求模块
- src/parser/       # HTML/JSON解析模块
- src/pipeline/     # 数据存储与清洗
- tests/            # 单元测试

## 编码规范
- Python 3.10+，使用类型注解
- 适配器必须继承 BaseAdapter 基类
- 必须实现 parse_list() 和 parse_detail() 方法
- 使用 pytest + responses 进行测试
- 所有外部请求必须处理超时和重试

## 常用命令
- 运行测试: `pytest tests/ -v`
- 代码检查: `ruff check src/`
- 格式化: `black src/`

## 参考模板
- 新增适配器时，参考 `src/adapters/de_bag_adapter.py` 的完整写法

## 禁止事项
- 禁止修改 .env 文件
- 禁止在适配器中硬编码 URL 和凭证
- 禁止直接删除现有适配器，必须先注释再确认

关键原则：规则要具体、可验证。比如“代码要整洁”不如“适配器必须继承 BaseAdapter”有效。Pi 会逐级向上查找 AGENTS.md，将找到的内容拼接进系统提示中。

第二步：创建 Skills — 封装领域工作流

Skills 是按需加载的自包含能力包。Pi 启动时只扫描技能的名称和描述，当任务匹配时才加载完整的 SKILL.md，从而节省 Token。

创建技能目录：

mkdir -p ~/.pi/agent/skills/spider-adapter-generator

**编写 **SKILL.md（~/.pi/agent/skills/spider-adapter-generator/SKILL.md）：

---
name: spider-adapter-generator
description: 根据目标网站URL和参考模板，生成完整的爬虫适配器代码。适用于新增数据源。
---

# 爬虫适配器生成器

## 何时使用
当用户要求为新的网站或数据源生成爬虫适配器时使用。

## 工作流
1. 用 `read` 读取 `src/adapters/de_bag_adapter.py` 作为参考模板
2. 用 `read` 读取 `src/adapters/base_adapter.py` 了解基类接口
3. 如果用户提供了目标URL，尝试用 `bash` 执行 `curl -s <url> | head -500` 获取页面结构
4. 生成新的适配器文件到 `src/adapters/<source_name>_adapter.py`
5. 生成对应的测试文件到 `tests/test_<source_name>_adapter.py`
6. 运行 `pytest tests/test_<source_name>_adapter.py -v` 验证

## 输出要求
- 适配器必须继承 BaseAdapter
- 必须处理请求超时（默认10秒）和重试（最多3次）
- 必须包含完整的 docstring
- 解析逻辑必须处理空值和异常情况

创建后，在 Pi 中用 /skill:spider-adapter-generator 即可强制触发。你还可以让 Pi 帮你生成更多技能，比如“爬虫调试”、“选择器修复”、“数据管道测试”等。

第三步：配置子代理（Subagents）— 组建你的“虚拟团队”

子代理是独立的 Agent 实例，拥有自己的工具集和模型配置，适合处理并行或专业化的子任务。安装 pi-simple-agents：

pi install npm:pi-simple-agents

然后为你的项目定义几个子代理，放入 ~/.pi/agent/agents/：

侦察兵（只读代码分析） — scout.md：

---
name: scout
description: 只读代码库侦察，用于了解现有适配器模式、发现潜在问题
tools: read, grep, find, ls
model: newapi/gpt-4o-mini
---

你的任务是只读分析代码库，不修改任何文件。
报告发现时，用简洁的列表格式，包含文件路径和行号。
重点关注：现有的适配器模式、重复代码、潜在的异常处理缺失。

网页侦察兵（联网分析目标网站） — web-scout.md：

---
name: web-scout
description: 抓取目标网站并分析HTML结构，提取CSS选择器和数据模式
tools: read, write, bash
model: newapi/gpt-4o-mini
---

使用 curl 或 MCP 工具获取目标页面，分析并报告：
1. 列表页和详情页的 URL 模式
2. 标题、价格、描述等字段的 CSS 选择器
3. 分页机制（URL参数、下一页按钮等）
4. 数据是静态渲染还是 JavaScript 动态加载
5. 是否存在反爬机制（Cloudflare、验证码等）

将分析结果写入 `docs/<source_name>_analysis.md`。

代码审查员 — reviewer.md：

---
name: reviewer
description: 审查代码质量，检查是否符合项目规范
tools: read, grep, find
model: newapi/gpt-5.6-luna
---

以严格的代码审查者角度，检查：
1. 是否继承 BaseAdapter 并实现必要方法
2. 异常处理是否完整（超时、重试、空值）
3. 是否有硬编码的 URL 或凭证
4. 测试覆盖率是否足够
输出格式：按严重程度分级（Critical/Warning/Info）

使用方式：在 Pi 中直接说“用 scout 分析 src/adapters/ 目录下所有适配器的共性模式”，Pi 会自动调用 subagent 工具。也支持并行调用多个子代理。

第四步：配置 MCP — 赋予联网爬取能力

Pi 默认没有联网能力，需要通过 MCP（Model Context Protocol）连接外部服务。安装适配器：

pi install npm:pi-mcp-adapter

然后创建 ~/.pi/agent/mcp.json，配置一个网页抓取 MCP 服务器。以 Scrapeless 为例：

{
  "mcpServers": {
    "scrapeless": {
      "command": "npx",
      "args": ["-y", "scrapeless-mcp-server"],
      "env": {
        "SCRAPELESS_API_KEY": "your-api-key-here"
      }
    }
  }
}

MCP 适配器采用懒加载机制——服务器只在 Agent 实际调用其工具时才启动，因此即使配置多个 MCP 服务器，也不会膨胀上下文预算。配置完成后，web-scout 子代理就能真正访问目标网站，而不是依赖训练数据中的过时信息。

实战工作流：用你的 Agent 重构爬虫

配置完成后，一个完整的爬虫迁移任务可以这样执行：

场景：为 example.com 新增爬虫适配器。

你：为 https://example.com 的新数据源生成适配器

Pi 的行动链：
1. /skill:spider-adapter-generator 触发技能
2. subagent web-scout → 抓取 example.com，分析 HTML 结构，写入 analysis.md
3. subagent scout → 读取现有适配器模板和基类接口
4. 主 Agent 基于分析结果和模板，生成 example_adapter.py 和 test_example_adapter.py
5. subagent reviewer → 审查生成的代码
6. 运行 pytest 验证
7. 报告结果

批量重构场景：

你：分析 src/adapters/ 下所有适配器，找出没有处理超时的，统一修复

Pi 的行动链：
1. subagent scout → 遍历所有适配器，列出缺少 timeout 处理的文件
2. 主 Agent 逐个修复（用 edit 工具）
3. subagent reviewer → 批量审查修改
4. 运行完整测试套件

核心操作技巧

操作 命令 用途
引用文件 @src/adapters/base.py 将文件内容加入上下文
执行命令 !pytest tests/ -v 运行命令并让 Pi 看到输出
静默执行 !!git status 仅终端执行，不进入上下文
触发技能 /skill:spider-adapter-generator 强制加载指定技能
切换模型 /model newapi/gpt-5.6-luna 会话中动态切换模型
调整推理 /thinking none 关闭或调整推理强度
引用文件分析 @src/adapters/ + 指令 批量分析目录

Token 优化建议：日常适配器生成用 gpt-4o-mini（$ 0.15/ $0.60），子代理也用 gpt-4o-mini 以控制成本。只有复杂的架构决策或难以定位的 bug 才切换到 gpt-5.6-luna。子代理的模型可以在其 .md 文件的 frontmatter 中单独指定。

常见问题

Q：技能没有被自动触发怎么办？
用 /skill:<name> 手动触发。Pi 的模型不总是主动去读取技能文件，手动触发可以保证执行。

Q：子代理修改了我不希望它改的文件？
在子代理的 frontmatter 中严格限制 tools 字段。比如 scout 只给 read, grep, find, ls，不给 write 和 edit。

Q：如何让子代理继承主会话的模型选择？
在子代理 frontmatter 中写 model: inherit 即可。

Q：MCP 服务器启动失败怎么办？
先用 bash 手动运行 MCP 服务器的启动命令，确认它能独立工作后再配置到 mcp.json 中。
