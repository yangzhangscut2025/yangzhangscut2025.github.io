reCAPTCHA 处理方案技术指南

2026-09-13 · 预计阅读 12 分钟 技术教程

一、版本识别与核心特性

处理前必须先确认目标网站的 reCAPTCHA 版本，因为不同版本的风控逻辑和解决方案完全不同。

版本 加载入口 调用方式 界面表现 典型站点
v2 api.js grecaptcha.render 勾选框 + 图片挑战 传统网站
v3 api.js grecaptcha.execute 无界面，返回 0-1 分数 一般网站
Enterprise（俗称 v4） enterprise.js grecaptcha.enterprise.execute 默认无感，高风险弹出图片或 QR 挑战 政府、金融、法务

识别方法：

  1. 查看页面加载的 JS 地址。api.js 为普通版，enterprise.js 为企业版。
  2. 检查调用函数。grecaptcha.execute 为普通版，grecaptcha.enterprise.execute 为企业版。
  3. 观察行为。v3 永不弹出界面，企业版会在高风险时弹出挑战。

核心检测维度（所有版本共有）：浏览器指纹、WebDriver 标记、鼠标行为、IP 信誉、页面交互时序。

二、解决方案分类

按实现机制划分为四类，从零成本到生产级依次递进。

2.1 环境伪装类（零成本，概率性）

通过隐藏自动化特征、模拟真人行为提高通过率。不能保证 100% 通过，适合风控不严的站点。

技术手段：

手段 工具 说明
隐藏自动化标记 playwright-stealth 抹除 navigator.webdriver 等特征
指纹伪造 Camoufox 在 C++ 层伪造 WebGL、Canvas、字体指纹
行为模拟 Pydoll 模拟真实鼠标移动、点击

代码示例：

from playwright.sync_api import sync_playwright
from playwright_stealth import stealth_sync

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)
    page = browser.new_page()
    stealth_sync(page)
    page.goto("目标页面")

局限：图片选图挑战无法处理，v3 严格打分场景可能失败，IP 质量差时直接必出验证码。

2.2 第三方打码 API 类（付费，生产常用）

调用第三方服务获取有效 token，成功率高，是生产环境推荐方案。

主流服务商：

服务商 特点
CapSolver AI 驱动，支持 v2/v3/Enterprise，提供行为模拟
2Captcha 人工 + 自动混合，提供浏览器扩展
CapMonster Cloud 支持 v3 的 minScore 和 pageAction 参数

工作流程：

  1. 从页面提取 sitekey 和当前 URL
  2. 调用打码服务 API，提交 sitekey、URL、pageAction
  3. 等待服务返回 g-recaptcha-response token
  4. 将 token 注入页面，提交表单

代码示例：

# 1. 提取 sitekey
site_key = page.locator("[data-sitekey]").get_attribute("data-sitekey")

# 2. 调用打码服务获取 token
token = captcha_client.solve_recaptcha_v3(
    site_key=site_key,
    page_url=page.url,
    page_action="submit",
    min_score=0.7
)

# 3. 注入 token
page.evaluate(f"""
    document.querySelector('[name="g-recaptcha-response"]').value = '{token}';
""")

# 4. 模拟前置行为后提交
page.wait_for_timeout(500)
page.locator("form").submit()

优缺点：

  • 优点：稳定适配 v2/v3/Enterprise，无需处理图片识别
  • 缺点：按次计费，单次耗时 5-15 秒，大批量并发成本较高

2.3 本地开源解法（免费，仅限 v2）

利用 v2 的音频挑战配合本地语音识别，仅支持 v2，v3 和 Enterprise 无界面不适用。

代表项目：playwright-recaptcha

局限：网站更新音频接口即失效，不适合大规模生产。

2.4 浏览器扩展（调试专用）

扩展 用途
Buster 音频自动解 v2，适合手动调试

不适合自动化批量执行。

三、得分优化最佳实践

适用于 v3 和 Enterprise 的静默打分场景。网站通常设置阈值（如 0.5），低于阈值被拒绝。

优化项 说明
pageAction 匹配 传递与站点一致的 action 值，大小写敏感
浏览器 stealth 使用 playwright-stealth 或 undetected-chromedriver
住宅代理 数据中心 IP 得分 0.0-0.3，住宅 IP 得分 0.5-0.7
Cookie 预热 复用 Google 服务的 cookies，保存 storage_state
鼠标行为 自然轨迹，避免瞬移
页面停留 真人停留 10-30 秒再操作
避免 wait_for_timeout 该 API 发送 CDP 命令，可被检测
优先 Playwright Puppeteer 发送更多 CDP 流量，更易被检测

常见阈值参考：

站点类型 阈值 难度
个人博客 0.3 容易
电商 0.5 中等
银行 0.7 难
Enterprise 0.8+ 很难

四、Enterprise 版本（俗称 v4）专项

4.1 与普通 v3 的关键差异

项目 普通 v3 Enterprise
JS 入口 api.js enterprise.js
调用方法 grecaptcha.execute grecaptcha.enterprise.execute
界面 永不弹窗 高风险弹出图片或 QR 挑战
Token 校验 标准签名 额外 enterprise 签名
Sitekey 格式 6Le 开头 与 Google Cloud 项目绑定

4.2 打码服务任务类型

版本 任务类型
普通 v3 ReCaptchaV3TaskProxyLess
Enterprise ReCaptchaV3EnterpriseTaskProxyLess

任务类型传错会导致 token 被后端直接拒绝，是高频踩坑点。

4.3 必须传入参数

  1. websiteURL：页面完整 URL
  2. websiteKey：页面 sitekey
  3. pageAction：enterprise.execute 的 action 字符串
  4. minScore：建议 0.7

4.4 Token 注入两种方案

方案一：表单隐藏域

page.evaluate(f'document.querySelector("[name=g-recaptcha-response]").value="{token}"')

方案二：覆盖原生 execute（企业版网站主流方式）

page.evaluate(f"""
    window.grecaptcha.enterprise.execute = function(key, opt) {{
        return Promise.resolve("{token}");
    }}
""")
page.locator("#submit-btn").click()

五、高频踩坑点

  1. v3 无勾选框。v3 是后台打分，不是点选验证。IP 差、指纹差直接拿低分被拒。
  2. Headless 模式指纹泄露。Chromium 旧无头模式容易被识别，优先使用 headless=False。
  3. IP 权重高于脚本伪装。代理 IP 在黑名单池时，再好的 stealth 脚本也会疯狂触发验证。
  4. Token 不能立即提交。需模拟鼠标滑动、页面停留，Google 校验行为时序链。
  5. Enterprise 模式动态切换。同一 sitekey 可能静默打分，也可能弹出图片挑战，代码需兼容两种情况。
  6. Enterprise token 有额外签名。普通 v3 任务产出的 token 在企业版网站直接作废。
  7. QR 挑战。Enterprise 高风险时新增 QR 扫码挑战，普通 v2/v3 任务处理不了。
  8. 指纹检测深度。Enterprise 检测 DevTools 协议、浏览器内部时序、Privacy Sandbox 信号，headless 模式几乎必翻车。

六、方案选择决策

场景 推荐方案
风控不严、偶尔弹出 环境伪装类（stealth + 行为模拟）
生产环境、v2/v3 第三方打码 API
Enterprise 版本 第三方打码 API（必须用 Enterprise 任务类型）
本地调试 v2 Buster 扩展
v3 静默打分 得分优化 + 住宅代理

核心结论：开源方案只在 v2 场景有效，v3 和 Enterprise 依赖第三方打码 API 是当前最可靠的路径。高防护站点（Enterprise 阈值 0.8+）可能无法绕过，需要评估合规性。
