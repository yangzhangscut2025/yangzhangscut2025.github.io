Claude Code 使用指南（上）：命令与配置体系

2026-07-24 · 预计阅读 14 分钟 AI学习

关于本系列：三篇文章系统梳理了 Claude Code 的使用方法论。上篇讲命令与配置，中篇讲记忆系统，下篇讲协作技巧。适合已经安装配置完毕、想要系统提升 AI 协作效率的开发者。上一篇 Claude Code + DeepSeek + VS Code 配置流程 覆盖了安装和基础配置，本篇是其延续。

一、命令全景图

Claude Code 的斜杠命令可以分成四类：

类别 命令 一句话概括
对话管理 /clear /compact /cost /output-style 控制对话本身
项目配置 /init /config /add-dir /doctor /statusline /update 设置和诊断环境
开发辅助 /review /pr-comments 围绕代码的工作
扩展管理 /memory /permissions /mcp /ide 记忆、权限、集成

下面逐个展开，按实用频率排序。

二、对话管理

/compact — 压缩上下文

场景：聊了很久，上下文窗口快满了，AI 开始"忘记"早期讨论的内容。

作用：自动把前面的对话做一次摘要，释放空间。摘要会保留关键信息（已做的决策、正在进行的任务、项目背景），丢掉冗余的轮次。

何时用：

  • 系统自动提示上下文快满时
  • 你感觉 AI 开始"失忆"时
  • 主动运行，提前清理空间

注意：压缩后，被精简掉的对话细节确实丢失了。如果某个细节很重要，在压缩前让 AI 记下来（比如写到 CLAUDE.md 或 /memory）。

/clear — 清空对话

场景：话题完全切换，旧对话没有参考价值了。

作用：完全清空当前对话历史，从头开始。相当于"重启"。

与 /compact 的区别：/compact 保留摘要，/clear 什么都不留。

建议：切换项目或任务时用，日常用 /compact 就够了。

/cost — 查看消耗

场景：想知道这轮对话用了多少 token、花了多少钱。

作用：显示当前会话的 token 消耗统计。

/output-style — 输出风格

场景：想让 AI 回答更简洁，或者更详细。

作用：切换输出风格。可选值包括默认风格和更简洁的风格。如果觉得 AI 输出太啰嗦，可以调成简洁模式；需要详细解释时再切回来。

三、项目配置

/init — 初始化项目记忆

场景：新项目接入 Claude Code，想让 AI 理解这个项目。

作用：分析项目结构，生成 CLAUDE.md 文件。这个文件会每次会话自动加载，作为 AI 的项目记忆。

CLAUDE.md 是什么：放在项目根目录的 Markdown 文件，内容是给 AI 看的项目规则——

  • 项目是做什么的
  • 目录结构是怎样的
  • 操作流程是什么
  • 有哪些约定和规范

示例（我的 Hugo 博客项目的 CLAUDE.md 片段）：

## 工作原则
- 先读再改：修改文件前必须先阅读当前内容
- 先计划再执行：非简单操作先给方案，用户确认后再动手
- 遵守工具流：所有博客操作严格按照本文档执行

关键原则：CLAUDE.md 里写的是不会变的事（项目规则、流程、约定），不是会变的事（具体任务、临时决定）。

后续中篇会专门讲 CLAUDE.md 的写法。

/config — 配置设置

场景：调整 Claude Code 的行为，比如权限策略、模型选择。

作用：打开配置界面，可以修改：

  • 权限模式：什么操作需要确认
  • 模型选择：用哪个底层模型
  • 其他行为设置

下面第五节和第六节会详细讲权限和配置。

/add-dir — 多目录项目

场景：项目代码分散在多个目录（比如前端和后端在不同文件夹）。

作用：把额外的目录加进 Claude Code 的工作范围，AI 就能跨目录操作。

/doctor — 环境诊断

场景：Claude Code 出问题了——连不上、命令报错、安装失败。

作用：自动检查运行环境（Node.js 版本、网络连通性、工具安装状态等），输出诊断结果。

什么时候跑：

  • 安装后验证环境
  • 出现莫名其妙的错误
  • 升级版本后确认兼容

/statusline — 状态栏定制

场景：定制终端底部状态栏显示什么信息。

作用：选择状态栏显示的内容，比如当前模型、token 用量、会话时长等。

/update — 版本更新

场景：有新版本发布了。

作用：检查并更新到最新的 Claude Code 版本。

四、开发辅助

/review — 代码审查

场景：改完代码，想找找有没有 bug、安全隐患、性能问题。

作用：对当前改动做代码审查，输出发现问题列表。

使用建议：提交前跑一次，相当于多一个免费的审查人。

/pr-comments — PR 评论

场景：GitHub 上收到了 PR 评论，想让 AI 帮助理解和处理。

作用：拉取 PR 评论，辅助分析和回复。

五、扩展管理

/memory — 持久化记忆

场景：想让 AI 记住一些跨会话的东西，比如你的偏好、项目背景。

作用：管理持久化记忆。与 CLAUDE.md 的区别：

  • CLAUDE.md：存在项目里，跟着项目走，全队共享
  • /memory：存在本地，跟着你走，所有项目都能用

适合存什么：

  • 个人偏好（“我喜欢用中文输出”）
  • 常用工作流习惯（“我习惯先看方案再动手”）
  • 跨项目的参考信息

中篇会详细讲。

/permissions — 权限管理

场景：控制 AI 做什么操作需要你确认。

作用：设置权限策略。AI 在处理时会根据设置的规则决定"直接做"还是"先问"。

三种权限模式：

  • 总是允许：这类操作不再询问
  • 每次都询问：默认模式，每次操作都会确认
  • 始终拒绝：直接拒绝，AI 不会尝试

常见操作类型：读写文件、执行命令、网络请求、Git 操作等。

一个实际问题的说明：有时你会看到界面提示"permission denied"但并不是你点了拒绝——可能是权限策略设置的问题。用 /permissions 检查和调整即可。

/mcp — MCP 工具配置

场景：想给 Claude Code 接入外部工具——数据库直连、自定义 API、企业内部系统。

作用：管理 MCP（Model Context Protocol）服务器。MCP 是 Claude Code 的工具扩展机制，相当于给 AI 装"插件"。

什么时候需要：

  • 让 AI 直接查数据库
  • 连接企业内部 API
  • 接入自定义工作流工具

日常写代码一般不需要，属于进阶功能。

/ide — IDE 集成

场景：你在 VS Code 或 JetBrains 里用 Claude Code，想调整集成行为。

作用：管理 IDE 集成相关设置。

六、权限系统详解

权限系统是 Claude Code 的"安全阀门"。每次 AI 要执行可能造成影响的动作（写文件、删文件、执行命令、网络请求），都会触发权限检查。

四种动作结果

当你看到权限弹窗时，通常有这几个选项：

选项 含义
允许本次 这次让 AI 执行，下次同样的操作还会问
总是允许 这个类型的操作以后不再问，AI 直接做
拒绝本次 这次不让 AI 执行
始终拒绝 这个类型的操作永远拒绝

实际使用策略

刚上手时保持默认（什么都问），用了几天后你对 AI 的操作有了信任感，可以把一些低风险操作设为"总是允许"：

  • 读文件 → 设为允许（AI 只看不改，没风险）
  • 搜索代码 → 设为允许
  • 写文件 → 保持询问（防止误改）
  • 执行命令 → 保持询问（防止误删）

一个常见误区：看到 AI 操作之前每次都要确认觉得烦，就全部放行。不建议这样做——至少写文件和执行命令应该保留确认。

七、/config 配置详解

运行 /config 进入配置界面后，主要设置项：

权限策略

就是上一节讲的内容，在这里可以统一修改。调整后对应操作类型的默认行为会改变。

模型选择

Claude Code 支持多种底层模型，你可以根据需求和预算切换。不同模型在速度、能力、价格上有差异。

工作区信任

可以设置哪些目录是"受信任的"，在受信任的目录中权限策略更宽松。

其他设置

包括自动压缩阈值、输出风格默认值等行为参数。

八、小结与下篇预告

上篇覆盖了 Claude Code 的四类命令和权限、配置体系。核心要点：

  1. 日常必知：/clear（重启）、/compact（释放空间）、/cost（看消耗）
  2. 项目管理：/init（创建项目记忆）、/config（调整行为）
  3. 权限策略：默认保持询问，低风险操作可放行，高风险操作保留确认
  4. 环境排障：出问题先跑 /doctor
