AI 编程工具使用体验与成本控制经验

2026-09-13 · 预计阅读 6 分钟 AI学习

记录2026年八到九月份个人在代码生成和适配器开发中使用过的 AI 工具，以及成本控制的经验教训。

一、Claude Code

接入方式：VSCode 插件

初期配置：通过 cc-switch 接入 GPT 和 DeepSeek 的模型

使用体验：

  • VSCode 插件形态比终端舒服，交互直观
  • 一开始用 Terra 模型搭框架，效果很好
  • Token 消耗较大

问题：

  • 插件形态的上下文管理比较激进，容易消耗大量 Token
  • 与 Codex 一起使用后，两个工具合计有时一天花费 100 美金

二、Codex

接入方式：CLI

使用体验：

  • 体感上和 Claude Code 差不多
  • 粒度没有 Claude Code 细，适合做粗一点的活
  • 接原生 GPT 模型

问题：

  • 同样耗费 Token
  • 一开始用 Codex 读整个旧代码库，Token 消耗直接超标

教训：

  • 不要让 AI 读整个代码库。应该先做侦察，明确需要读哪些文件，再让 AI 有针对性地读取。

三、Copilot

申请背景：GPT 额度用完，转申请 Copilot

使用体验：

  • 默认使用 auto 模式选择模型，通常表现一般
  • 需要非常详细地阐述任务和代码实现逻辑，才能得到较好结果
  • 接入 Claude 模型后表现明显更聪明

问题：

  • Claude 模型价格较高，额度很快用完

教训：

  • Copilot 的 auto 模式不等于自动选择最优模型，需要手动指定
  • 用便宜的模型做框架性工作，用贵的模型做关键细节，比全程用贵模型更经济

四、Cursor

使用背景：Copilot 额度用完后，看到 Cursor 有免费额度，尝试使用

使用体验：

  • 有免费额度，可以试用
  • 接入了一个荷兰数据源的爬虫任务，一个对话就用完了免费额度
  • 但从任务结果看，效果不错

问题：

  • 免费额度很少，一个中等复杂度的任务就能耗尽
  • 继续使用需要付费，成本需要评估

评价：

  • 功能上可用，验证性尝试的效果符合预期
  • 免费额度适合做小规模验证，不适合长期开发

五、Pi Agent

选型背景：

  • 新额度到位后，决定控制用量
  • 在 Pi Agent 和 DeepSeek Harness 之间权衡
  • 最终选择 Pi Agent，因为轻量、稳定、适合了解 AI 工作原理

当前配置：

  • 接入 GPT 模型，主要使用 Luna
  • 通过 New-API 网关监控用量
  • 搭建了项目专属的 Skills 和子代理

使用体验：

  • 整体好用
  • 轻量设计使得启动快、Token 消耗可控
  • 通过 New-API 网关可以实时看到每次调用的成本

关键差异：

  • Pi 把上下文控制和模型选择权交给用户，而不是自动决策
  • 配合 New-API 的额度限制，能有效避免超额

六、成本控制经验

6.1 初期的问题

Claude Code 和 Codex 并行使用期间，有时一天消耗 100 美金。主要原因：

  • 两个工具同时开着，都消耗 Token
  • 让 AI 读整个代码库，上下文极大
  • 没有额度限制，用超了才发现

6.2 控制措施

措施 工具 效果
网关层额度限制 New-API 令牌额度 硬性上限，超额直接拒绝
会话层预算拦截 pi-budget-guard 超标阻止工具调用
任务层轮次限制 pi-turn-limit 防止死循环
模型分级使用 Luna（日常）+ Terra/Sol（难题） 降低单次成本
侦察与生成分离 Pi Skills 避免重复探索消耗

6.3 关键经验

不要把 AI 当搜索引擎用。 让它读整个代码库，不如先明确要解决什么问题，再针对性读取。

不要同时开多个 AI 工具。 每个工具都在消耗 Token，并行使用等于成本翻倍。

先规划后执行。 让 AI 先输出方案，确认后再动手，比一路试错省 Token。

用便宜的模型做框架。 Luna 可以完成大部分日常编码任务，只有复杂架构决策才需要升级到 Terra 或 Sol。

有额度上限才安全。 没有限制的 API Key 等于没有刹车，New-API 的令牌额度是最后一道防线。

免费额度只能做验证。 Cursor 的免费额度验证了效果，但一个任务就耗尽，不适合承担开发主力。

八、工具演进路径

团队的使用路径呈现出一条清晰的成本控制演进线：

Claude Code + Codex（并行）
    ↓ 一天 100 美金，成本失控
Copilot（auto 模式）
    ↓ 需要详细描述，Claude 模型额度用完
Cursor（免费额度）
    ↓ 一个任务就用完，仅够验证
Pi Agent + New-API（多层额度控制）
    ↓ 当前方案

核心转变：从"追求最强模型"到"追求可控成本下的最优配置"。

九、给新人的建议

  1. 先用有额度限制的网关，不要直接暴露原始 API Key
  2. 从 Pi Agent 开始，它的轻量设计能让你看清 AI 工作的每一个环节
  3. 不要并行使用多个 AI 工具，除非你能清楚知道每个工具的成本
  4. 记录每次任务的 Token 消耗，建立成本基线，才能判断什么时候该用贵模型
  5. 读代码库之前先侦察，明确目标再让 AI 读取
  6. 免费额度只做验证，验证完再决定是否付费
