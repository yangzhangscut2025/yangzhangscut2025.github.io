Pi Agent + New-API 配置与使用教程

2026-09-13 · 预计阅读 10 分钟 技术教程

0- 为什么需要 pi 和 New-API？

  • pi 是轻量的 agent，内置提示词少，省 token。
  • 通过 New-API 网关可以实时看到每次调用的成本，防止用超额度

一、前置条件

  • 操作系统：Windows / Linux / macOS
  • Node.js：20 或更高版本
  • Docker：已安装并运行（Windows 建议使用 Docker Desktop）

二、部署 New-API（API 网关）

New-API 负责统一管理模型渠道、令牌额度和调用日志。

1. 拉取并运行容器

在 PowerShell 或终端中执行以下单行命令：

docker run --name new-api -d --restart always -p 3000:3000 -e TZ=Asia/Shanghai -v D:/new-api-data:/data calciumion/new-api:latest

注意：镜像名称为 calciumion/new-api，这是当前维护最活跃的版本。数据目录 D:/new-api-data 可按需修改，但不要使用包含空格的路径。

2. 初始登录与安全设置

浏览器访问 http://localhost:3000，默认账号 root，密码 123456。登录后立即修改默认密码。

3. 配置渠道

进入「渠道」页面，点击「添加渠道」：

配置项 填写内容
类型 选择你的模型提供商（如 OpenAI、DeepSeek）
名称 自定义，便于识别
密钥 填入你的真实 API Key
模型列表 留空（使用所有模型）或填写指定模型，如gpt-4o-mini
代理 如网络受限，填写代理地址（如http://127.0.0.1:7890）

保存后点击「测试」验证渠道是否可用。

4. 创建令牌（用于 Pi 调用）

进入「令牌」页面，点击「新建令牌」：

配置项 说明
名称 如Pi 开发令牌
额度 建议设置硬性上限（如 5.00 美元），这是控制成本的关键
过期时间 可选
模型权限 留空表示允许所有模型
IP 白名单 可选

提交后立即复制生成的 sk- 令牌，后续 Pi 配置需要使用。

三、安装与更新 Pi

1. 安装 Pi（如尚未安装）

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

2. 更新 Pi（推荐）

当前最新版本已修复此前 Windows 上的配置读取问题：

pi update

更新后确认版本：

pi --version

四、配置 Pi 连接 New-API

1. 创建或编辑 models.json

文件路径：C:\Users\你的用户名\.pi\agent\models.json（Windows）或 ~/.pi/agent/models.json（macOS/Linux）

内容如下：

{
  "providers": {
    "newapi": {
      "baseUrl": "http://127.0.0.1:3000/v1",
      "api": "openai-completions",
      "apiKey": "sk-你的NewAPI令牌",
      "compat": {
        "supportsReasoningEffort": false
      },
      "models": [
        {
          "id": "gpt-4o-mini",
          "name": "GPT-4o mini",
          "api": "openai-completions",
          "reasoning": false,
          "input": ["text"],
          "cost": { "input": 0.15, "output": 0.60, "cacheRead": 0, "cacheWrite": 0 },
          "contextWindow": 128000,
          "maxTokens": 16384
        },
        {
          "id": "gpt-5.6-luna",
          "name": "GPT-5.6 Luna",
          "api": "openai-responses",
          "reasoning": false,
          "input": ["text"],
          "cost": { "input": 0.20, "output": 1.20, "cacheRead": 0, "cacheWrite": 0 },
          "contextWindow": 200000,
          "maxTokens": 16384
        }
      ]
    }
  }
}

关键字段说明：

字段 说明
baseUrl New-API 地址，必须包含 /v1 后缀
api openai-completions 或 openai-responses，根据模型选择
apiKey New-API 生成的令牌
compat.supportsReasoningEffort 设为false 可阻止 Pi 发送 reasoning_effort 参数
reasoning false 表示非推理模型
cost 用于 Pi 显示费用估算

关于 openai-responses：gpt-5.6 系列模型在 chat/completions 端点下与工具一起使用时会报错，需使用 responses 端点。

2. 重载配置

在 Pi 中执行：

/reload

3. 切换模型

/model newapi/gpt-4o-mini

发送测试消息，确认正常响应。

五、额度控制（多层防护）

层级 方式 说明
网关层（硬性） New-API 令牌额度 在 New-API 后台设置令牌额度，达到上限后拒绝调用
Pi 内置 spending-guard 默认每会话上限 $3.00，可用/spending limit 1.00 调整
扩展层 pi-budget-guard 安装后可设置enforce 模式，超标阻止工具调用
对话轮数 pi-turn-limit 限制单会话轮数，默认 25 轮

推荐组合：New-API 令牌额度 + pi-budget-guard，双重保障。

六、常见问题

问题 原因 解决
reasoning_effort 400 错误 Pi 发送了模型不支持的参数 在models.json 中为对应模型设置 reasoning: false 和 compat.supportsReasoningEffort: false
模型无响应或超时 baseUrl 未生效 确认models.json 路径正确，执行 /reload
镜像拉取失败 镜像名错误 使用calciumion/new-api:latest
修改models-store.json 无效 该文件为自动生成缓存 应修改models.json

七、注意事项

  1. 不要修改 models-store.json：这是 Pi 自动生成的缓存文件，修改后会被覆盖。
  2. 模型 ID 区分大小写：必须使用全小写，如 gpt-5.6-luna。
  3. gpt-5.6 系列使用 openai-responses 端点：否则会返回 400 错误。
  4. 定期备份 models.json：配置完成后建议备份，便于迁移或恢复。
  5. 关注版本更新：Pi 迭代较快，遇到问题时优先检查是否为已知回归，可查阅官方文档或社区讨论。

配置说明：

  • 模型 ID 与 API：gpt-5.6 系列（Luna/Terra/Sol）必须使用 "api": "openai-responses"，因为它们在 chat/completions 端点下与工具（function tools）一起使用时会报错。gpt-4o 系列则使用 "api": "openai-completions"。
  • 推理能力（reasoning）：Luna 被设置为 false（非推理模式），Terra 和 Sol 设置为 true。Sol 和 Terra 支持更长的推理过程，适合复杂任务。
  • 上下文窗口：gpt-5.6 系列的 contextWindow 设为 200000，参考了相关配置示例。
  • 成本：根据文档更新的价格，Luna 为 $ 1/ $6，Terra 为 $ 2.50/ $15，Sol 为 $ 5/ $30。

附录二：简短经验总结

操作路径：

  1. 配置 New-API：在 Windows Docker 中部署 calciumion/new-api。
  2. 创建令牌：在 New-API 后台创建一个有足够额度的令牌。
  3. 编写 models.json：按照上面的完整配置，将所有模型写入 ~/.pi/agent/models.json。
  4. 切换模型：在 Pi 中使用 /model newapi/gpt-5.6-luna 等命令切换模型。
  5. 验证：发送消息，确认模型能正常响应。

需要避开的坑：

  • API 端点：gpt-5.6 系列必须使用 openai-responses，不能用 openai-completions。
  • 推理参数：如果遇到 reasoning_effort 相关的 400 错误，检查是否错误地使用了 openai-completions 端点。
  • 成本：注意不同模型的计费差异，Luna 最便宜，Sol 最贵，根据任务选择合适模型。
